About

Cerulean is a small indie search engine. Built in a weekend in February 2026, maintained quietly since.

It is not trying to replace Google. It is trying to demonstrate that ad-free, AI-slop-filtered search can still be useful, and to be the search engine its builder actually wants to use.

This is a hobby. No ads. No profit motive. No data collection beyond what the server logs by default. No accounts.

Built by Garret Blanchette in Palm Springs, California. Code at github.com/garretblanchette/Cerulean-search.

Cerulean was started as an experiment in what someone with no prior development experience could build. The code, the site, and this about page were written in collaboration with Claude — Anthropic's Claude Opus 4.7 model, doing its best imitation of Garret's voice. That feels apt for a project this transparent about how it works.

How are search results categorized?

Every result is tagged with one of 10 categories based on the domain. The classification is a rule-based lookup, not ML, and it errs on the side of broad buckets so you can filter without getting lost in subcategories:

  • News — major news outlets, wire services, press releases
  • Reference — Wikipedia, dictionaries, encyclopedias, recipe sites, general factual references
  • Academic — .edu domains, scholarly publishers, peer-reviewed paper hosts
  • Official — .gov, .mil, and official institutional sources
  • Community — forums, social platforms, blogs, fan wikis — anywhere people are talking
  • Docs — technical documentation, tutorials, code hosts, programming learning sites
  • Shopping — commerce sites, product listings, review aggregators
  • Video — YouTube, Vimeo, video platforms
  • Health — medical references, health information sites
  • AI Content — pages flagged as likely AI-generated, hidden by default

Unknown domains fall through to "Other" and get no badge.

About the search providers

Brave — independent index. Different results than Google for the same query, with the best privacy posture of the three (no profiling, no tracking). The downside: smaller coverage on long-tail queries, and results are capped at 20 per search. Best default for most use cases.

Serper — thin wrapper around Google's own SERP. Best coverage and ranking quality, especially for obscure queries. The downside: your query is logged by a commercial intermediary before reaching Google, so it is the worst privacy option. Use it when Brave misses what you are looking for.

DuckDuckGo — free fallback, mostly Bing-derived results. Decent for general queries, no API cost. The downside: rate-limited and occasionally returns thin or stale results. Use it when the others fail or when you want a zero-cost option.

About the Highlights chip

The Highlights chip pulls representative sentences from your result snippets and shows them as bullets above the source list. It is extractive — no language model is involved — and it is off by default. The point is to help you triage which sources collectively cover the topic, not to replace reading them. This is intentionally different from Google's AI Overview, which generates a synthesized answer and pushes sources below.
