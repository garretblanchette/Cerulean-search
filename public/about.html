About

Cerulean is a small indie search engine. Built in a weekend in February 2026, maintained quietly since.

It is not trying to replace Google. It is trying to demonstrate that library science principles can be operationalized at search scale by an indie project, and to be the search engine its builder actually wants to use.

This is a hobby. No ads. No profit motive. No data collection beyond what the server logs by default. No accounts.

Built by Garret Blanchette in Palm Springs, California. Code at github.com/garretblanchette/Cerulean-search.

Cerulean was started as an experiment in what someone with no prior development experience could build. The code, the site, and this about page were written in collaboration with Claude, Anthropic's Claude Opus 4.7 model, doing its best imitation of Garret's voice. That feels apt for a project this transparent about how it works.

How results are classified

Every classified result gets tagged on two axes: source role (primary, secondary, tertiary) and source type (journalism, academic, indie, commercial, and others). The framework, the three-tier classifier pipeline, and the honest limits are documented on the Methodology page.

Current production state. Source-type tags are live. Source-role tags are rolling out. The methodology page describes the target system in full and is updated as production catches up.

Search providers

Brave. Independent index. Different results than Google for the same query, with the best privacy posture of the three (no profiling, no tracking). Smaller coverage on long-tail queries, and results are capped at 20 per search. Best default for most use cases.

Serper. Thin wrapper around Google's own SERP. Best coverage and ranking quality, especially for obscure queries. Your query is logged by a commercial intermediary before reaching Google, so it is the worst privacy option. Use it when Brave misses what you are looking for.

DuckDuckGo. Free fallback, mostly Bing-derived results. Decent for general queries, no API cost. Rate-limited and occasionally returns thin or stale results. Use it when the others fail or when you want a zero-cost option.

Top sentences

Top sentences pulls representative sentences from result snippets and shows them as bullets above the source list. Extractive. No language model involved. Off by default. The point is to help you triage which sources collectively cover the topic, not to replace reading them. This is intentionally different from Google's AI Overview, which generates a synthesized answer and pushes sources below.

The AI-content filter

The AI-content filter is a heuristic estimate, not a verdict. It looks at signal patterns in titles and snippets that correlate with machine-generated text. It has no access to the full page, no model trained on the specific generator that produced any given result, and no way to confirm authorship. Treat the tag as a flag, not a fact.

How it fits the two-axis taxonomy. The filter is one structural signal feeding the "SEO farm" and "aggregator" source-type classifications. False positives on legitimate technical or formulaic writing cost the user very little. False negatives cost more, especially against well-resourced bot-farm content, commercial astroturfing, and state-sponsored operations that do not announce themselves. The higher-order defense is the one search has always relied on: independent human scrutiny of the source you land on.
